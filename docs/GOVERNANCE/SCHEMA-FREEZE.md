# تجميد هيكل قاعدة البيانات (Database Schema Freeze)

> **القانون:** قاعدة البيانات تملك **بيانات حقيقية** لعميل في السوق. الهيكل **مجمَّد**. الكود يتكيّف مع القاعدة — **لا العكس**. (`AGENTS.md` §2.42 · `RULE-N198`)

## 1. ممنوع نهائياً (بلا استثناء)

| ممنوع | لماذا |
|---|---|
| `DROP TABLE` / `DROP COLUMN` | يفقد بيانات لا تُستعاد |
| إعادة تسمية جدول أو عمود | يكسر كل استعلام وشاشة و`Models` قائمة |
| تغيير نوع بيانات (`ALTER COLUMN`) أو تضييق طوله | قد يقصّ بيانات موجودة |
| إزالة علاقة (`FK`) أو `CHECK` قائم | يفتح باب بيانات يتيمة/سالبة |
| `CASCADE DELETE` | يحذف صفوفاً لم يقصدها أحد |
| `UPDATE` جماعي يعيد كتابة قيم قائمة «لتصحيحها» | يمحو تاريخ العميل |

## 2. مسموح — بشروط

**الزيادة الآمنة فقط، وبموافقة مالك مكتوبة ومؤرَّخة:**

| مسموح | الشرط |
|---|---|
| جدول جديد كلياً | لا يمسّ جدولاً قائماً |
| عمود جديد | `NULL` أو `DEFAULT` — لا `NOT NULL` بلا قيمة افتراضية على جدول فيه بيانات |
| فهرس جديد | غير فريد، أو فريد بعد التحقق من عدم وجود تكرار |
| `CHECK` جديد | لا يرفض صفوفاً قائمة (يُفحص قبل الإضافة) |

## 3. سلّم البدائل — قبل أن تطلب تعديلاً (إلزامي)

1. **عمود قائم** يحمل المعنى؟ استخدمه.
2. **جدول `SystemSettings`** (مفتاح/قيمة)؟ هذا هو الحل المعتمد للإعدادات.
   **سابقة مقيسة في هذا المستودع:** «ألوان النظام» و«إعدادات التنسيق» حُفظتا في `SystemSettings` القائم — **بلا كيان جديد ولا ترحيل** (`AGENTS.md` §2.20 بند 14 و16).
3. **جدول جديد** (لا يمسّ القائم).
4. **عمود جديد** (`NULL`/`DEFAULT`).
5. **الرفض المُبلَّغ:** «هذه الميزة تحتاج تعديل هيكل — تحتاج قرار المالك» + البديل الأقرب من 1–4.

> الوكيل الذي يقترح تعديل هيكل «لتسهيل الكود» **عمله يُرفض**، ويُعاد بسلّم البدائل.

## 4. بروتوكول التنفيذ عند الموافقة (خمس خطوات)

1. **موافقة مكتوبة** من المالك في ملف المهمة: النص الحرفي + التاريخ.
2. **تحديد النوع**: جدول جديد / عمود جديد / فهرس — لا أكثر في الترحيل الواحد.
3. **`database-engineer` وحده** يكتب: `Models/**` + `Configurations/**` + **ترحيل واحد**.
4. **تحقق من SQL المولَّد**: لا `DROP`، لا `ALTER COLUMN`، لا حذف فهرس قائم — يُقرأ الملف قبل التطبيق.
5. **خطة رجوع**: كيف تُلغى الإضافة إن فشلت (حذف الجدول/العمود الجديد وحده) — تُكتب في ملف المهمة.

## 5. قالب الموافقة (يلصق المالك نصه)

```
أوافق على الزيادة الآمنة التالية فقط: <جدول جديد / عمود جديد …>
الجدول: <اسم>   العمود: <اسم>   النوع: <…>   NULL/DEFAULT: <…>
التاريخ: <YYYY-MM-DD>              التوقيع: المالك
غير مسموح في هذه الموافقة: أي حذف أو إعادة تسمية أو تغيير نوع.
```

## 6. علاقة هذا القانون بقفل الباك-إند

ترتيب صارم، كل خطوة تسبق التي بعدها:
**تغطية Mock مؤهَّلة (`docs/MOCK-COVERAGE.md`) → مراجعة المالك للـMock → موافقة مكتوبة على السلوك (`RULE-N177`) → موافقة مكتوبة منفصلة على تعديل الهيكل (هذا الملف) → ترحيل إضافي واحد.**
وجود الموافقة على السلوك **لا يعني** الموافقة على تعديل الهيكل.

## 7. الاستثناءات الثلاثة الوحيدة (`RULE-N178`)

إصلاح خطأ بناء يمنع الترجمة · إصلاح أمني عاجل يُبلَّغ للمالك قبل التنفيذ · تصحيح يفرضه `AGENTS.md` نفسه (تسمية/دين معماري) — **بلا تغيير سلوك مالي**، وكل استثناء يُدوَّن باسمه وسببه في ملف المهمة. **ولا واحد منها يسمح بمسّ الهيكل.**
