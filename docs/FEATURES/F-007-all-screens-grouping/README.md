## 2) تعريف «الكتلة» (يُطبَّق على كل شاشة)

**كتلة = منطقة وظيفية يؤدي فيها المستخدم غرضاً واحداً**، وتُحاط بصندوق بعنوان عربي قصير يقول **ما هذه البيانات ولماذا**:

| الكتلة | المصدر النمطي | العنوان النمطي |
|---|---|---|
| شريط الأوامر | `pnlToolbar` / `pnlButtons` / `gbCommands` | «أوامر الشاشة» |
| بيانات السجل / المحرر | `pnlFields` / `pnlBody` / `gbInvoiceInfo` | «بيانات <الكيان>» |
| الإدخال السريع | `ctrlLineEntry` / `gbEntry` | «إضافة صنف» |
| الشبكة / التبويبات | `pnlGrid` / `tabMain` / `tabPayments` / `tabReturns` | «<السجلات>» · «فواتير البيع» · «المرتجعات» |
| البحث والتصفية | `pnlFilters` + **`gbFilter`** | «بحث وتصفية» — **قائم في معظم الشاشات** |
| الملخص | `pnlSummary` | «ملخص النتائج» |
| الإجماليات | `gbTotals` / `grpTotals` | «الإجماليات» |
| التلميحات | `pnlFooter` (عندما يحتوي `lblHint` فقط) | «تلميحات الاستخدام» |

**يبقى خارج الصناديق (سابقة المرجع — قرار `F-006/D-03`):**
- شريط العنوان `lblMode` / `pnlHeader` (يحتوي `lblMode` فقط)
- شريط الحالة الديناميكي `lblQuickInfo` / `lblInvoiceSummary`
- طبقات الفراغ/التحميل `emptyState` / `lblNoData` / `loadingPanel`
- `pnlTitle` في الحوارات الصغيرة (عنوان النافذة)
- `pnlFilters` نفسه (عارٍ يحتضن `gbFilter`) — لأن `FilterPanelHelper` يغيّر ارتفاعه أثناء الطيّ

## 4) لماذا 37 وكيلاً لا 5

`RULE-N156`: كل شاشة عقد تصميم مستقل — مصمّم 25–65 ك.ب ببنية إرساء مختلفة (`splitMain` · `tabMain` · `pnlFields` · `pnlBody`) وقواعد أعمال مختلفة (وضع إدخال · تعطيل · تصفية). الدمج يُنتج وكيلاً يعمل 4 ساعات ثم يفشل في شاشتين، والتشخيص يصير أصعب من العمل. `RULE-N159`: **4 وكلاء كحد أقصى في الموجة** ⇒ **12 موجة**.
