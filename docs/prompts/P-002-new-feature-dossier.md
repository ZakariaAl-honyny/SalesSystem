# P-002 — فتح ملف ميزة جديدة (Feature Dossier)

> يُستخدم مع **كل مهمة L** أو ميزة جديدة، **قبل** أول Brief.
> المرجع: `docs/FEATURES/README.md` · `AGENTS.md` §2.41 (`RULE-N197`).

---

## النص (انسخه كما هو)

```
TASK SHAPE: FEATURE DOSSIER (docs/FEATURES/F-NNN-<slug>/)

قبل أي كود:
1) انسخ docs/FEATURES/_TEMPLATE/ إلى مجلد جديد F-NNN-<slug>.
2) املأ README.md + BRIEF.md في نفس اليوم (لا لاحقاً).
3) أضف صفاً في docs/FEATURES/INDEX.md.
4) إن كانت المهمة «تعديل شامل على النظام»: أضف MANIFEST.md من _TEMPLATE (إلزامي).

المحتوى الإلزامي في README.md:
- الحالة · الحجم · المرحلة · الوكيل المالك · أثر قاعدة البيانات.
- قسم «⚠️ لا تكسر هذه» — ثلاثة أسطر على الأقل: سلوك قائم · مستهلك خارجي · حالة مجمَّدة.

المحتوى الإلزامي في BRIEF.md:
- داخل النطاق: قائمة ملفات **مغلقة** (لا مجلدات).
- خارج النطاق: ممنوع بالاسم (Business/** · DataAccess/** · Models/** · Services/Direct/** · كل شاشة أخرى…).
- العقود: التوقيعات حرفياً.
- أثر قاعدة البيانات: «لا شيء» افتراضاً، أو موافقة مكتوبة بالنص.

قبل التسليم:
- اكتب جولة جديدة في LOG.md (لا تعدّل جولة قديمة).
- حدّث README.md فقط إذا تغيّرت الحالة أو «لا تكسر هذه».

المخرج: مسارات الملفات الخمسة + الحالة + ما ينتظر المالك، بلا كلمة «تم» بلا دليل.
```

---

## متى تُستخدم بدل ملف المهمة العادي؟

| الحالة | الملف المطلوب |
|---|---|
| ميزة جديدة · وحدة · مسار بيانات · تعميم ≥ 3 شاشات | `docs/FEATURES/F-NNN/` (خمسة ملفات) |
| تعديل شامل (موجة كبيرة) | نفس المجلد **+ `MANIFEST.md`** |
| إصلاح صغير · دفعة S · خطأ بناء | `docs/TASKS/TASK-NNN-<slug>.md` (ملف واحد) |

**الخطأ الشائع:** فتح «مهمة كبيرة» كسجل مهمة واحد ⇒ تضيع تفاصيلها بعد أسبوعين وتُبدأ من الصفر. الميزة الكبيرة **مجلد**، لا ملف.
