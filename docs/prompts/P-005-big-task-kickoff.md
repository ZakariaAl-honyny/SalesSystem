# P-005 — بدء مهمة كبيرة (Big Task Kick-off)

> **يُلصق في بداية أي مهمة على مستوى النظام.** يفتح ملف التتبع، يضبط المؤشر التلقائي، ويُلزم كل وكيل بالملفات.
> المرجع: `RULE-N202` · `docs/GOVERNANCE/BIG-TASK-TRACKING.md` · `docs/TASKS/_BIG-TASK-TRACKER-TEMPLATE.md`.

---

## 1. النص (انسخه واملأ أربعة أسطر فقط)

```
BIG TASK — KICK-OFF

اسم المهمة: <مثال: توحيد أزرار كل الشاشات على اللوحة الجديدة>
الهدف بجملة: <ما يتغيّر بعد المهمة، وكيف نعرف أنه تغيّر>
ما أريد تعديله: <أنماط/مسارات — مثال: Screens/**/*.Designer.cs كافة>
ما لا يجوز لمسه: <مثال: Business/** · DataAccess/** · Models/** · Features المغلقة>

نفّذ بالترتيب — ولا تبدأ أي كود قبل إتمام 1→4:

1) اقرأ: AGENTS.md §2.41 (RULE-N198/N202) · docs/GOVERNANCE/BIG-TASK-TRACKING.md
   · docs/GOVERNANCE/SYSTEM-SWEEP.md · docs/GOVERNANCE/EVIDENCE.md
2) أنشئ ملف التتبع من docs/TASKS/_BIG-TASK-TRACKER-TEMPLATE.md باسم المهمة
   (نمط MangeSubaggentsAndTracProgress.md) في مكان واحد، واملأ:
   الرأس · داخل/خارج النطاق · الأعداد · لوحة الوكلاء · جرد الملفات.
3) الجرد بالأمر لا بالذاكرة: شغّل الأمر الذي ينتج قائمة الملفات، واكتب الناتج
   في «جرد الملفات» بأرقام صفوف. أعلن الأعداد الثلاثة قبل أي تعديل.
4) اضبط docs/TASKS/ACTIVE.md على «مفتوحة» + اسم المهمة + مسار ملف التتبع.
   (كل وكيل يقرأ هذا الملف أولاً بحكم برومبته — لا تُخبر أحداً يدوياً.)
5) قسّم موجات: ≤ 4 وكلاء · ≤ 8 ملفات لكل وكيل · مالك واحد لكل ملف · ملفات منفصلة تماماً.
   كل Brief يحمل: مسار ملف التتبع + أرقام صفوفه + «خارج النطاق» + ذيل الأدلة (P-004).
6) بعد كل موجة: dotnet build (0 أخطاء) ← حدّث لوحة الوكلاء والجرد والدليل ← الموجة التالية.
7) مراجعة واحدة (code-reviewer) على المنتهي — لا لكل ملف.
8) الإغلاق: طابِق الأعداد (المُكتشَف = داخل + معفى · داخل = مُنجَز + متبقٍ) ·
   فحص بقايا grep = 0 · أعِد ACTIVE.md إلى «لا توجد مهمة كبيرة مفتوحة» ·
   **ابقِ ملف التتبع** (سجل مراجعة — لا يُحذف).

قواعد ثابتة أثناء التنفيذ:
- لا تعديل هيكل قاعدة بيانات بلا موافقة مكتوبة منفصلة (RULE-N198).
- لا «تم/كل/يعمل» في أي تقرير بلا أمر ومخرج (RULE-N196).
- أي عائق يوقف وكيلاً يُسجَّل في §8 من ملف التتبع، ولا يُتجاوَز بصمت.

التسليم النهائي: جدول «ما تم» + الأعداد الثلاثة + البناء + الكومِت + قائمة اختبار عربي +
بنود مفتوحة بصراحة + السطر الأخير: لم يُكتب أي اختبار آلي — الاختبار مسؤولية المالك.
```

---

## 2. اختبار التوصيل (أول 60 ثانية — تأكّد أن الملفات تعمل فعلاً)

اطلب من الوكيل قبل أي عمل أن يُعيد **خمسة أسطر** فقط:

```
1) مسار ملف التتبع الذي أنشأته:
2) الأعداد: المُكتشَف = … | داخل = … | معفى = …
3) حالة docs/TASKS/ACTIVE.md الآن:
4) أول موجة: الوكيل | الملفات (أرقام) | الحجم
5) الملفات التي لن تُلمس أبداً في هذه المهمة:
```

إن جاء أي سطر ناقصاً أو بلا رقم ⇒ **التوصيل مكسور**: أوقف قبل الموجة الأولى وأصلح الملف، لا الكود.

## 3. الأخطاء التي يمنعها هذا الـPrompt

| الخطأ | كيف يمنعه |
|---|---|
| البدء بالتعديل قبل الجرد | الخطوة 3 تسبق أي كود |
| نسيان ملفات | جرد بأمر + أعداد + فحص بقايا |
| وكيل يعمل بلا سياق | ACTIVE.md + مسار التتبع في كل Brief |
| تمدد صامت إلى ملفات خارج النية | «خارج النطاق» في الـBrief و§2 من الملف |
| تقرير «تم» بلا دليل | ذيل P-004 في كل Brief |
| فقدان الذاكرة بعد أسبوعين | ملف التتبع يبقى + سجل جولات إضافي |
